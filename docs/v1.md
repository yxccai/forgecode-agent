# V1: 从观察到修改

V0 只能读文件。V1 增加精确编辑、测试命令与 diff，把观察结果变成可验证的修改。

## 阅读路线

`v1/agent.py` 仍是显式循环；`HumanMessage / AIMessage / ToolMessage` 表达协议语义。
`v1/tools.py` 使用 `StructuredTool` 与 Pydantic schema，让工具接口与参数校验一致。
`v1/model.py` 只负责 LangChain 模型适配和流式事件，终端仍在 `forgecode/ui.py`。

## 设计选择

- 编辑：要求 old 精确匹配一次，避免行号漂移或不确定批量替换；失败后模型重新读取文件。
- 执行：参数数组、不经过 shell、30 秒超时、输出截断、清理进程组；命令需要人工确认。
- 上下文：按完整 assistant/tool 组保留近期消息，避免孤立工具结果。字符预算是近似值，不等于模型 token 数。
- 结果：模型必须查看测试与 diff；V1 暂时依赖提示词约束，V4 将用运行时验证约束完成状态。

命令确认不是安全沙箱：被批准的 Python 或测试代码仍拥有当前用户的权限。
V1 直接修改目标目录；执行前应保留自己的工作。V4 才加入 worktree 隔离。

## 验证

测试覆盖编辑歧义、路径边界、命令拒绝、命令超时，以及实际编辑后运行 unittest 的完整循环。
真实模型验收脚本 `scripts/validate_coding.py --windows-env` 使用临时 Git 仓库；
模型需要修复 add，验收器独立运行测试并检查测试文件未被修改。

2026-09-21 验证通过：9 个自动化测试通过；真实模型使用 5 次工具调用，
依次读取 app.py、test_app.py、编辑 app.py、执行 unittest、查看 git_diff。
验收器独立执行 2 个测试全部通过，diff 仅将 `a - b` 改为 `a + b`，测试未被修改。
轨迹显示模型未按要求先跑失败基线，说明仅靠提示词无法强制执行顺序，留给可靠执行阶段解决。
