# V0: 原始工具调用循环

问题：先理解模型如何请求工具，以及运行时如何把观察结果送回模型。

设计：不引入 Agent 框架。使用标准库 HTTP + SSE；工具集合限制为 read_file、search、list_files。
以目录列举代替 shell 命令，V0 没有执行任意命令的需求。工具错误也作为观察返回模型。
每轮结束保存完整 assistant 消息，然后按 tool_call_id 追加工具结果。

代表任务：临时仓库 app.py 包含 add 函数，本地协议服务发出分片 read_file 调用，运行时读取实际文件，回传带行号内容，随后输出引用 app.py:1 的回答。
该固定响应服务验证协议与执行链路，不评估模型理解能力。

重要边界：工作记忆就是 messages；轨迹是追加事件日志，不是恢复点；Rich 渲染完全独立于核心。
模型的隐藏推理不可观测，等待动画只表达请求状态。

已知限制：没有编辑、shell、checkpoint、上下文总预算；只限制工具单次输出与最大模型步数。
路径约束不是操作系统沙箱，用户不应把包含敏感文件的目录交给 Agent。
