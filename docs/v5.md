# V5: 用证据比较机制

V5 不增加 Agent 能力，最新入口复用 V4。新增模块只负责任务集、验收、评测与报告。

## 任务与验收

`v5/tasks.py` 包含 20 个独立任务：12 个修复、6 个功能、2 个重构。
每次创建全新的 Git 仓库与 worktree，放入 subject.py、一个公开测试和 24 个干扰模块。
模型工作区没有参考实现或隐藏用例。结果源码复制到独立临时目录，由 `oracle.py` 执行全部用例。
重构任务还使用 AST 检查结构约束；修改公开测试会导致任务失败。
所有初始实现必须无法通过完整验收，参考实现必须通过，自动化测试强制检查这个前提。

这些是人工编写的教学基准，不是 SWE-bench，也不能代表真实大型项目的表现。
测试生成、真实开源 issue 和自然语言理解暂不纳入，以保持验收客观和范围可理解。

## 运行与复现

```bash
forgecode-eval --suite smoke --config config.local.json
forgecode-eval --suite matrix --workers 3 --out .forgecode/my-evaluation
python -m v5.report .forgecode/my-evaluation --output docs/my-evaluation.md
```

开发仓库内可附加 `--windows-env`，读取 Windows 的 FORGECODE 环境变量；不会输出密钥。
`full` 执行 20 个完整配置任务。`matrix` 执行这 20 个任务及四组各 5 个任务的配对消融，共 40 次。
任务顺序用固定 seed=42 打乱；API 生成本身仍有随机性。`--repeats` 支持重复实验。
结果逐条追加；使用相同输出目录可跳过已完成项继续，配置不一致则拒绝复用。
程序只存储模型标识和数据集指纹，不存储 endpoint 或 key。轨迹可能包含代码，默认不上传。

## 消融假设

| 开关 | 实际变化 | 要回答的问题 |
|---|---|---|
| no_planning | 去掉额外 Plan 模型调用 | 简短任务上计划是否值得额外开销？ |
| no_context | 去掉自动排名大纲和符号工具，保留基础搜索 | 路径/符号线索是否减少搜索与读取？ |
| no_verification | 去掉强制基线、最终验证和修复回路 | 运行时验证是否比模型自行决定验证更可靠？ |
| no_memory | 不检索或提供记忆工具 | 已有仓库说明是否减少探索成本？ |

记忆组使用相同来源可验证的仓库约定，内容只有代码/测试位置和测试命令，没有答案。
这是 warm orientation 消融；不是长期自然任务历史的记忆收益评测。
no_verification 下模型仍可调用测试工具，因此不应将结果解释为“从不测试”。

## 指标与结论约束

成功要求独立验收、结构约束和运行终止均成功。Test pass rate 按独立用例数计算。
Steps 包含 Plan；tokens 使用提供商 usage；latency 包含网络；files_read 只统计显式 read_file。
上下文索引扫描在 V3 已单独说明，不应混淆为模型文件读取。
四组消融仅有 5 对任务、默认重复一次，不能据此声称统计显著或架构全面优越。
失败分类保持保守，不凭轨迹自动断言“推理能力不足”；必要时人工回看工具错误和实际 diff。

结果与逐任务指标见 `evaluation-v5.md` 和 `evaluation-v5.json`。

## 实验审查修正

首轮 no_verification 任务额外去掉了测试命令提示，导致模型请求其它命令并被固定审批策略拒绝。
这会混淆“提示不同”和“强制验证不同”。修正后所有组使用完全相同的任务提示，
只改变运行时开关；单独重跑这 5 项，并保留首轮原始记录。
可用 `--variant no_verification` 重跑该组，报告的 `--replacement-directory` 明确选用修正后的数据。

## 本次实测结论（2026-09-21）

使用配置模型 qwen3.7-flash、提供商默认推理强度，最终 40 项有效记录全部通过独立验收。
完整配置的 20 项任务平均 15367 tokens、37.95 秒、5.4 次工具调用。
下表只比较相同 5 个任务，差值为“关闭机制 - 完整配置”：

| 关闭机制 | 成功率差值 | 平均 token 差值 | 平均延迟差值 |
|---|---:|---:|---:|
| 计划 | 0 | -814 | -24.76 秒 |
| 仓库上下文 | 0 | +686 | +0.46 秒 |
| 强制验证 | 0 | +2775 | +4.83 秒 |
| 持久记忆 | 0 | +409 | +1.58 秒 |

在这组简单任务中，额外计划没有显示成功率收益，且增加了开销。
上下文、验证和记忆的配对成本差异较小或受模型行为影响，不能从单次小样本归因出普遍收益。
所有组都只读取 2 个文件，未观察到减少模型文件读取的效果。
没有失败任务，因此无法从本轮识别主导失败模式；失败分类器已实现，但缺少实际失败分布。
后续应增加多文件依赖和真实开源任务，重复实验并报告区间，而不是宣称当前 100% 等于生产可靠。

21 个自动化测试通过；其中 20 个基准的初始代码均被拒绝、参考代码均通过。
验证修复回路的失败分支由确定性模型决策配合实际编辑/测试覆盖；本轮真实模型未产生可用于统计的修复失败案例。
