# V3: 仓库上下文与记忆

V2 没有文件选择机制，面对大目录时容易反复列目录和盲读文件。
V3 先用 Git 文件清单（尊重 gitignore），再用路径、词法匹配、Python AST 符号和 import 信息排序。
`repo_map` 返回有限文件大纲，`find_symbols` 返回定义位置，源文件仍由模型按需读取。

阅读顺序：`repository.py` -> `tools.py` -> `memory.py` -> `agent.py`。
复用 V2 的状态图、V1 的编辑执行工具，避免为每一版复制相同代码；版本提交历史保存当时的完整快照。

## 检索不等于记忆

- 检索基于当前源码索引，回答“这次任务相关的代码在哪里”。
- 记忆保存跨任务经验，回答“此前在这个仓库学到什么”。
- semantic 与 episodic 共用 SQLite 存储，但用 kind 区分；都必须提供来源路径。
- 记忆包含源文件 SHA-256、创建时间和置信度，V3 尚不主动淘汰失效来源。
- 模型可以把错误结论写入记忆，指纹只证明来源未变化，不证明结论正确。

默认最多扫描 5000 个文本文件，每文件 500 KB；上下文大纲最多 8 个文件、8000 字符。
目前 AST 只支持 Python，其它语言保留路径和词法匹配；不引入向量数据库。
`estimated_tokens` 是字符数/4 的粗估计，真实输入 token 以提供商 usage 为准。

## 指标口径

索引器为了提取符号会在本地扫描源码，这些读取不能算成“完全没读”。
`indexed_files` 记录本地索引扫描数；`files_read` 记录模型主动调用 read_file 的文件数。
完整源码不会因为建立本地索引就全部进入模型上下文。
测试仓库由真实 Python 模块组成，但含 100 个生成的干扰模块，不代表生产级复杂项目。
